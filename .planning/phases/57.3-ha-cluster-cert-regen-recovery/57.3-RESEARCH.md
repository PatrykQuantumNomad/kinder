## Summary

Phase 57.3 fixes Phase 52's `RegenerateEtcdPeerCertsWholesale` recovery path. The current implementation renews only `etcd-peer` (etcd↔etcd on port 2380). The forensic evidence on `uat-58-01` proves the failure is on the apiserver→etcd path (port 2379), which uses `etcd-server` (presented by etcd) + `apiserver-etcd-client` (presented by apiserver). All three diagnostics in Plan 01 Task 0 are oriented at confirming this hypothesis with three independent signal sources.

The fix has four sub-deliverables: (1) widen the cert scope from `etcd-peer` to a per-cert-type renew-then-cycle loop covering up to 4 cert types per CP, (2) replace the static 20s `staticPodRecreationWait` with an active `etcdctl endpoint health` poll plus a new explicit `kube-apiserver.yaml` cycle + healthz poll, (3) add a first-class `--strategy=<auto|ip-pin|cert-regen>` flag on `kinder resume` so UAT can force the cert-regen path even after Phase 57.4 restores `ip-pin` as the default, (4) net-new `hack/uat-57.3-cert-regen.sh` covering IPv4, IPv6, and dual-stack fixtures.

**Primary recommendation:** Reuse the established lifecycle-package patterns (`certRegenSleeper` package-level var for time injection; `defaultCmder` for exec injection; `loggerFn`-style hooks for fakeable verbs). Add `etcdHealthChecker` and `apiserverHealthChecker` as package-level vars in `pkg/internal/lifecycle/certregen.go`. Add `Strategy string` field to `ResumeOptions`. Reuse `etcdctlAuthArgs`-style shared cert tuple (already established at `pkg/internal/doctor/resumereadiness.go:85` and `pkg/internal/lifecycle/pause.go:277`). The UAT script template is `hack/uat-57.2-ipv6-listener.sh` (per-fixture log subdir, default-fail trap pattern, kubectl-ready-poll with extended deadline).

## 1. kubeadm certs renew internals

**Confidence: HIGH** — verified from kubernetes.io official docs.

### Cert paths (authoritative)

All etcd-related certs live under `/etc/kubernetes/pki/`. Exact files:

| Cert subcommand | Cert file | Key file | Consumer | Cycle target |
|---|---|---|---|---|
| `etcd-server` | `/etc/kubernetes/pki/etcd/server.crt` | `/etc/kubernetes/pki/etcd/server.key` | etcd (`--cert-file` / `--key-file`) | `etcd.yaml` |
| `etcd-peer` | `/etc/kubernetes/pki/etcd/peer.crt` | `/etc/kubernetes/pki/etcd/peer.key` | etcd (`--peer-cert-file` / `--peer-key-file`) | `etcd.yaml` |
| `etcd-healthcheck-client` | `/etc/kubernetes/pki/etcd/healthcheck-client.crt` | `/etc/kubernetes/pki/etcd/healthcheck-client.key` | etcd liveness probe (etcdctl from within etcd container) | `etcd.yaml` |
| `apiserver-etcd-client` | `/etc/kubernetes/pki/apiserver-etcd-client.crt` | `/etc/kubernetes/pki/apiserver-etcd-client.key` | kube-apiserver (`--etcd-certfile` / `--etcd-keyfile`) | `kube-apiserver.yaml` |

**Note the path asymmetry:** `apiserver-etcd-client.{crt,key}` lives directly under `/etc/kubernetes/pki/`, NOT under `/etc/kubernetes/pki/etcd/`. This is intentional — kubeadm groups certs by "who is the principal" (apiserver → pki/, etcd → pki/etcd/).

### Cycle-target mapping (confirms CONTEXT.md decision §2)

The CONTEXT.md mapping is correct:
- Renewing `server.crt` / `peer.crt` / `healthcheck-client.crt` requires etcd to reload them → cycle `/etc/kubernetes/manifests/etcd.yaml`.
- Renewing `apiserver-etcd-client.crt` requires kube-apiserver to reload it → cycle `/etc/kubernetes/manifests/kube-apiserver.yaml`.

**Source:** [Kubernetes — PKI Certificates and Requirements](https://kubernetes.io/docs/setup/best-practices/certificates/) (HIGH confidence)

### Behavior of `kubeadm certs renew <subcommand>`

- Renewals run **unconditionally** regardless of cert expiration date.
- Extra attributes (SANs) are **based on the existing file/certificates** — no need to resupply.
- Default behavior uses the local PKI CA managed by kubeadm; alternatives (Kubernetes cert API, external CSR) are explicit `--use-*` flags we are NOT touching.
- **Important:** "After renewal, in order to make changes effective, it is required to restart control-plane components and eventually re-distribute the renewed certificate in case the file is used elsewhere." — kubeadm does NOT cycle pods for you. The mv-out/sleep/mv-in cycle in `RegenerateEtcdPeerCertsWholesale` (current `certregen.go:142-166`) is the manual restart.

**Source:** [Kubernetes — kubeadm certs renew](https://kubernetes.io/docs/reference/setup-tools/kubeadm/kubeadm-certs/) (HIGH)

### Subcommand availability

All four subcommands (`etcd-peer`, `etcd-server`, `etcd-healthcheck-client`, `apiserver-etcd-client`) are available in **all kubeadm versions kinder supports** (current kindest/node is K8s v1.35.1 per uat-58-01 forensic capture, line 8). The subcommand-per-cert API has been stable since at least K8s 1.15 (PR kubernetes/kubernetes#77863). No version-compat concern for kinder's supported matrix.

## 2. etcd readiness gate idiom (the new active poll)

**Confidence: HIGH** — verified against existing in-repo precedent.

### Canonical invocation (already in repo)

The codebase already has a fully working `etcdctl endpoint health` pattern at `pkg/internal/doctor/resumereadiness.go:85-90` and again at `pkg/internal/lifecycle/pause.go:277-284`. It is invoked via `crictl exec` into the etcd static-pod container (because kindest/node rootfs does NOT have etcdctl on $PATH; only the etcd container image does). The pattern is:

```go
// pkg/internal/doctor/resumereadiness.go:85
var etcdctlAuthArgs = []string{
    "--cacert=/etc/kubernetes/pki/etcd/ca.crt",
    "--cert=/etc/kubernetes/pki/etcd/peer.crt",       // peer.crt is what's in /etc/kubernetes/pki/etcd/, bind-mounted by kubelet
    "--key=/etc/kubernetes/pki/etcd/peer.key",
    "--endpoints=https://127.0.0.1:2379",
}
// 1. Discover running etcd container via crictl
etcdIDLines, _ := node.Command("crictl", "ps", "--name", "etcd", "-q").Output()
// 2. crictl exec etcdctl
healthArgs := append([]string{"crictl", "exec", <id>, "etcdctl"}, etcdctlAuthArgs...)
healthArgs = append(healthArgs, "endpoint", "health", "--cluster", "--write-out=json")
```

### What to reuse vs change for the ready-gate

For the **ready-gate poll** (NOT the diagnostic dump):
- **Use `endpoint health` not `endpoint status`** — simpler, returns boolean per-member; the poll cares about "is etcd up enough to serve" not "who's leader".
- **Drop `--cluster`** — for the ready-gate we want only the local member's health (because we just cycled THIS CP's etcd; quorum-wide health is a different question and is not required for this gate).
- **Keep `--write-out=json`** so we can reliably parse `[{health: true, ...}]`.
- **Cert pair:** Use `peer.crt`/`peer.key` for auth — exactly as the existing pattern at `resumereadiness.go:85`. This is the cert pair already proven to authenticate against etcd-server from inside the etcd container. It does NOT need to be `apiserver-etcd-client.{crt,key}` for the gate (that cert is used by the apiserver-healthz poll's downstream traffic).
- **Backoff:** Poll every 1s up to 60s (CONTEXT.md decision). Mirrors `WaitForNodesReady`'s 500ms loop at `resume.go:514-526` but with a 1s tick because etcd readiness is coarse-grained (10ms tick wastes CPU; 1s is plenty).

### Reusable helper

There is an exact precedent for parsing the JSON output at `pkg/internal/doctor/resumereadiness.go:263-275`:
```go
func parseEtcdHealth(rawJSON string) (healthy, total int, err error)
```
This function is **in a different package** (`pkg/internal/doctor`) — calling it cross-package from `pkg/internal/lifecycle` would create a layering inversion (lifecycle currently does not depend on doctor). Two options for the planner:
- **Option A:** Copy-paste the 12-line parser into `certregen.go`. Cheap, no layering issue, minor duplication.
- **Option B:** Promote `parseEtcdHealth` to a small shared subpackage (e.g. `pkg/internal/etcdhealth`). Cleaner but adds scope.

**Recommendation:** Option A. The function is tiny, the schema is etcd-stable, and 57.3 is a recovery-path fix, not a refactor.

## 3. Kubelet static-pod manifest pickup behavior

**Confidence: HIGH** — kubelet behavior verified against Kubernetes docs; in-repo constant matches.

### How kubelet detects manifest changes

- Default kubelet `fileCheckFrequency` is **20s** (verified against Kubernetes default and confirmed by `certregen.go:40` constant `kubeletFileCheckFrequency = 20 * time.Second`).
- Kubelet polls `/etc/kubernetes/manifests/` every `fileCheckFrequency`. When a manifest disappears, kubelet stops the corresponding static pod; when a manifest reappears (or content changes), kubelet starts a new one.
- The existing 25s pre-cycle sleep in `certregen.go:152` (`kubeletFileCheckFrequency + staticPodCycleSafetyMargin`) is correctly sized to **guarantee kubelet has noticed the manifest is gone before we put it back**. CONTEXT.md keeps this sleep.

### Why mv-out / sleep / mv-in works

This is the standard "static pod cycle" idiom. The mv-out step removes the manifest from kubelet's watched directory; the sleep window gives kubelet's 20s file-check loop time to fire and stop the pod; the mv-in step restores the manifest, triggering kubelet to start a fresh pod that reads the new cert files from disk on startup.

### What can go wrong if you mv-in too fast

If `mv-in` happens before kubelet has noticed the `mv-out`, kubelet sees the manifest "always present, content unchanged" and **does NOT restart the pod**. The new cert files exist on disk but the running etcd process has them cached/never reloaded. Symptom: cert serial changes per `openssl`, but etcd still presents the old cert because the process never restarted. This is exactly the failure mode the 25s sleep prevents.

The CONTEXT.md decision keeps this sleep. There is **no** active polling alternative for kubelet pickup — there is no kubelet API to "wait until you've noticed". You either wait `fileCheckFrequency + margin` or you race.

### Why we DON'T need a similar sleep on mv-in

After mv-in, the second `fileCheckFrequency` tick will start the pod. We don't need to sleep for that tick to fire — we instead **poll etcd readiness** (the new active gate). The pod will appear when kubelet polls; etcd will then take 3-5s to come up; the active poll detects success and proceeds. Total: 20-30s instead of the current 20s static wait. Slightly slower in the worst case but **always correct** vs. the current "trust the sleep" approach.

### Template for `hack/uat-57.3-cert-regen.sh`

**Use `uat-57.2-ipv6-listener.sh` as the structural base** because:

## 7. IPv6 + dual-stack loopback handshake nuance

**Confidence: MEDIUM** — kubernetes/kubernetes PR #64670 is authoritative for the kubeadm probe address logic, but kindest/node-specific etcd-listen behavior on dual-stack networks is empirically verified by the existing `etcdctlAuthArgs` constant working on IPv4 + IPv6 + dual fixtures.

### The single source-of-truth rule

From [kubernetes/kubernetes PR #64670](https://github.com/kubernetes/kubernetes/pull/64670/files):

> "if ip.Equal(net.IPv4zero) { return "127.0.0.1" } if ip.Equal(net.IPv6zero) { return net.IPv6loopback.String() }"

kubeadm's etcd liveness probe selects the loopback address **based on the cluster's IPFamily**, not based on what addresses etcd happens to be listening on. The same rule applies to our ready-gate.

### Mapping to kinder's IPFamily label

Phase 57.2 stamps `io.x-k8s.kinder.ip-family=<ipv4|ipv6|dual>` on every cluster container. Phase 57.3 can read it via the existing `loadbalancer.ClusterIPFamily` helper (returns `bool ipv6`) OR can read it directly via `docker inspect`.

### Endpoint addressing per family

| IPFamily label | etcd endpoint | curl healthz endpoint |
|---|---|---|
| `ipv4` | `https://127.0.0.1:2379` | `https://127.0.0.1:6443/healthz` |
| `ipv6` | `https://[::1]:2379` | `https://[::1]:6443/healthz` |
| `dual` | `https://127.0.0.1:2379` (etcd binds dual via `::` with `ipv4_compat`; either loopback works) | `https://127.0.0.1:6443/healthz` (same) |

**Important:** `etcdctl` does NOT auto-translate `0.0.0.0` → `127.0.0.1` or `::` → `::1`. We MUST pass the correct loopback per family. The bracket notation `[::1]:2379` is required for `etcdctl --endpoints`.

### Decision for the ready-gate code

Read the label once at the start of `RegenerateEtcdPeerCertsWholesale` (which already has access to `cpNodes`; use `cpNodes[0]` to read the label). Build the endpoint string accordingly:

```go
ipv6, _ := loadbalancer.ClusterIPFamily(binaryName, cpNodes[0])
endpoint := "https://127.0.0.1:2379"
healthzURL := "https://127.0.0.1:6443/healthz"
if ipv6 {
    endpoint = "https://[::1]:2379"
    healthzURL = "https://[::1]:6443/healthz"
}
```

The `loadbalancer.ClusterIPFamily` boolean already collapses `dual` → `true` (Phase 57.2 decision). Dual-stack picks the IPv6 loopback — works fine because etcd on dual-stack listens on `::` which accepts `[::1]` and the IPv4-mapped form.

### Verification

The existing `etcdctlAuthArgs` constant at `resumereadiness.go:85` hardcodes `https://127.0.0.1:2379` and is used successfully on the doctor-check path for IPv4 clusters. The IPv6 forensic snapshot at `.planning/phases/57.2-fix-discoverlbipv6-derive-from-cluster-ipfamily/uat-logs/ipv6-diag.txt` shows the cluster's `lds.yaml` listening on `::` with `ipv4_compat: true` — meaning the IPv6 dual-stack accept path works, but the cert-regen ready-gate has never been exercised against an IPv6-only cluster. Phase 57.3 UAT fixture `CLUSTER_IPV6` will be the first time this code path runs on an IPv6 cluster.

## 9. Common Pitfalls

### Pitfall 1: Mid-pass quorum loss from a too-fast cross-CP loop

**What goes wrong:** If the loop moves from cp1 to cp2 before cp1's etcd is genuinely re-joined to the cluster (just because kubelet started the pod), cp2's mv-out can drop a second etcd member while cp1's etcd is still doing leader election. Result: 2/3 etcd members down momentarily → quorum loss → all CPs hang trying to write.

**Why it happens:** The current 20s static sleep is "long enough" by accident for the happy path on most hardware. Slow disks or contention can push etcd's startup past 20s, especially on cp2 + cp3 which start with stale-leader-election state.

**How to avoid:** Per-CP **active** etcd-health gate (the locked CONTEXT.md decision). Hard-fail if the local etcd isn't healthy within 60s. This guarantees the next CP's mv-out only fires after the previous CP's etcd is fully back.

**Warning signs:** UAT log shows `etcdserver: request timed out` or `failed to send heartbeat` on the bootstrap CP during cp2 or cp3's regen window.

### Pitfall 2: `kubeadm certs renew <type>` silently failing on older kubeadm

**What goes wrong:** Hypothetically — older kubeadm doesn't recognize the cert-type subcommand and exits 0 with a "no-op" message. We'd then cycle the manifest and end up with the OLD cert still in use.

**Why it happens (not for this phase):** Subcommand-per-cert API has been stable since K8s 1.15. The kindest/node images kinder supports today (1.30+) all have the full set.

**How to avoid:** Capture stdout/stderr of every `kubeadm certs renew` call. After all four renews on a CP, run `kubeadm certs check-expiration -o json` and assert every regenerated cert's `notAfter` is in the future (post-pass verification per CONTEXT.md decision §2).

**Warning signs:** check-expiration shows `notAfter` unchanged compared to a pre-renew snapshot.

### Pitfall 3: Static-pod cycle race (mv-in before kubelet noticed mv-out)

**What goes wrong:** Sleep too short between mv-out and mv-in → kubelet doesn't re-detect the manifest → process never restarts → new cert files exist on disk but running process holds old certs in memory.

**Why it happens:** The 20s `fileCheckFrequency` default is upper-bound; kubelet may have JUST polled when we mv-out, so we need up to 20s + safety margin.

**How to avoid:** Keep the existing `kubeletFileCheckFrequency + staticPodCycleSafetyMargin = 25s` sleep (CONTEXT.md). Do NOT replace this sleep with active polling — there is no kubelet API for "have you noticed".

**Warning signs:** `openssl x509 -serial` on the cert file changes, but `crictl ps` shows the etcd container `CREATED` timestamp is OLD (i.e., process never restarted).

### Pitfall 4: `crictl logs` retention too short for diagnostic dump

**What goes wrong:** kubelet/containerd's log retention defaults can be aggressive on small disks. The diagnostic dump's "last 20 lines of `crictl logs kube-apiserver`" may return only the most recent attempt, missing the earlier crash signatures.

**Why it happens:** `crictl logs` reads from containerd's log path which truncates per-container. On uat-58-01 we observe 9 crash attempts of kube-apiserver (line 47 of forensic log) — containerd may keep only the latest few.

**How to avoid:** The diagnostic dump runs `crictl logs --tail 20 <id>` on whichever apiserver container is **currently** running (or the most recently exited). Accept that we may only see ATTEMPT N, not ATTEMPT N-K. Document this in the dump output. For richer history, the dump can also write `docker logs <cp-container>` (the host-level container log captures kubelet's view of pod events, which records each apiserver crash + reason) as a supplementary signal.

**Warning signs:** Dump shows `<no logs>` or only a few lines.

### Pitfall 5: IPv6-stack `etcdctl` defaulting to v4 loopback

**What goes wrong:** Forgetting to swap `127.0.0.1` → `[::1]` for IPv6 clusters → `etcdctl` returns `dial tcp 127.0.0.1:2379: connect: connection refused` because etcd is listening on `[::]:2379` and the IPv4 socket family is rejected.

**Why it happens:** The codebase's existing `etcdctlAuthArgs` constant at `resumereadiness.go:85` hardcodes `127.0.0.1`. Copy-pasting it for the new ready-gate without adjusting for IPFamily is a high-risk regression vector.

**How to avoid:** Build the endpoint dynamically per cluster, reading the IPFamily label up-front (see §7 of this research). Do NOT hardcode. Add a test fixture for the IPv6 path specifically. Phase 57.3 UAT script's `CLUSTER_IPV6` fixture is the integration-level guard.

**Warning signs:** IPv6 UAT fixture hangs at the etcd ready-gate; cp1's etcd is reported healthy by an in-container `etcdctl` invocation against `[::1]:2379` but our gate says unhealthy.

### Pitfall 6: `kubeadm certs check-expiration` exit code

**What goes wrong:** Assuming exit-code-non-zero means "a cert is expired" — actually the exit code is 0 unless the command itself fails to read the certs. Expired certs are reported via the `notAfter` column being in the past, NOT via exit code.

**Why it happens:** Confusing kubeadm's exit-code contract with classical "exit-nonzero-on-warn" tools.

**How to avoid:** Use `-o json` (available per the Kubernetes 1.30+ docs) and parse the JSON; check each entry's `notAfter` against the current time. Do NOT rely on exit code for "all renewed".

**Warning signs:** Post-pass verification passes (exit 0) but a cert was actually not renewed.

### Pitfall 7: `apiserver-etcd-client.{crt,key}` consumed elsewhere

**What goes wrong:** Assuming only kube-apiserver reads these files. If another process (kubelet talking to apiserver, controller-manager, etc.) also caches them, cycling kube-apiserver.yaml alone may leave stale handles open.

**Verified state:** Per Kubernetes PKI docs (cited in §1), `apiserver-etcd-client.{crt,key}` is consumed ONLY by kube-apiserver (via `--etcd-certfile` / `--etcd-keyfile`). It is not used by kubelet, controller-manager, or scheduler — those have their own kubeconfigs (`/etc/kubernetes/kubelet.conf`, etc.) backed by different certs. Cycling `kube-apiserver.yaml` IS sufficient for `apiserver-etcd-client` pickup.

**How to avoid:** None needed — the architectural assumption holds. Note this in the cert-regen function godoc so a future maintainer doesn't second-guess.

### Pitfall 8: Removing `RegenerateEtcdPeerCertsWholesale` function name

**What goes wrong:** Renaming the function to `RegenerateEtcdCertsWholesale` (which would match the expanded scope) breaks the W2 invariant (function called as unqualified name from same package) and creates a noisy diff for the planner.

**How to avoid:** Per CONTEXT.md decision §1, preserve the function name. Add a godoc comment explaining the historical name vs. expanded behavior. The internal scope expansion is a function-body change only.

### Pitfall 9: Pause/resume snapshot leaderID stays unchanged across cert-regen

**What goes wrong:** After cert-regen, etcd's leader can change (because we sequentially restart all etcd pods). The doctor check at `resumereadiness.go:231-247` warns "etcd leader changed since pause" — which would now be a *false-positive* warning when triggered by 57.3's recovery path.

**How to avoid:** Not a blocker for 57.3 — the doctor check is an opt-in introspection step, not a Resume() exit condition. Note in the 57.3 ROADMAP entry that operators may see a "leader changed" warning after a cert-regen resume; this is expected. (If we want to suppress, that's a separate phase: gate the snapshot-leader check on `resume-strategy != cert-regen`.)

// pollEtcdHealthRealImpl polls etcd /health on the given CP node every `tick`
// up to `deadline`. Returns nil as soon as etcdctl reports the local member
// healthy. Returns a wrapped error on deadline.
//
// IPv6 awareness: caller must build the endpoint string per cluster IPFamily.
// See loadbalancer.ClusterIPFamily.
func pollEtcdHealthRealImpl(node nodes.Node, deadline, tick time.Duration, endpoint string) error {
    end := time.Now().Add(deadline)
    var lastErr error
    for time.Now().Before(end) {
        etcdIDLines, err := exec.OutputLines(node.Command("crictl", "ps", "--name", "etcd", "-q"))
        if err != nil || len(etcdIDLines) == 0 {
            lastErr = errors.Wrap(err, "etcd container not running")
            certRegenSleeper(tick)
            continue
        }
        etcdID := strings.TrimSpace(etcdIDLines[0])
        args := []string{
            "crictl", "exec", etcdID, "etcdctl",
            "--cacert=/etc/kubernetes/pki/etcd/ca.crt",
            "--cert=/etc/kubernetes/pki/etcd/peer.crt",
            "--key=/etc/kubernetes/pki/etcd/peer.key",
            "--endpoints=" + endpoint,
            "endpoint", "health", "--write-out=json",
        }
        out, execErr := exec.OutputLines(node.Command(args[0], args[1:]...))
        if execErr == nil {
            healthy, total, parseErr := parseEtcdHealth(strings.Join(out, ""))
            if parseErr == nil && total > 0 && healthy == total {
                return nil
            }
            lastErr = fmt.Errorf("etcdctl reports %d/%d healthy (parse err: %v)", healthy, total, parseErr)
        } else {
            lastErr = errors.Wrap(execErr, "etcdctl exec failed")
        }
        certRegenSleeper(tick)
    }
    return errors.Wrapf(lastErr, "etcd ready-gate timed out after %v", deadline)
}

// Injection point — tests swap to instant-OK / instant-fail.
var etcdHealthChecker = func(node nodes.Node, endpoint string) error {
    return pollEtcdHealthRealImpl(node, 60*time.Second, 1*time.Second, endpoint)
}

// parseEtcdHealth — small copy of pkg/internal/doctor/resumereadiness.go:263-275
// to avoid creating a lifecycle→doctor layering dependency.
func parseEtcdHealth(rawJSON string) (healthy, total int, err error) {
    var entries []map[string]interface{}
    if uErr := json.Unmarshal([]byte(rawJSON), &entries); uErr != nil {
        return 0, 0, fmt.Errorf("etcd health JSON parse: %w", uErr)
    }
    for _, e := range entries {
        total++
        if h, ok := e["health"].(bool); ok && h {
            healthy++
        }
    }
    return healthy, total, nil
}

### C. Per-cert renew-then-cycle skeleton (replaces current single etcd-peer loop)

```go
// certCycle holds the per-cert-type configuration for one renew-then-cycle iteration.
type certCycle struct {
    certName     string // e.g. "etcd-peer", "etcd-server", "apiserver-etcd-client", "etcd-healthcheck-client"
    manifestPath string // /etc/kubernetes/manifests/etcd.yaml or kube-apiserver.yaml
    backupPath   string // /tmp/<basename>-bak.yaml
    cycleKind    string // "etcd" or "apiserver" — selects which post-cycle health gate to use
}

var cycleForCertType = map[string]certCycle{
    "etcd-peer":               {"etcd-peer", "/etc/kubernetes/manifests/etcd.yaml", "/tmp/etcd-bak.yaml", "etcd"},
    "etcd-server":             {"etcd-server", "/etc/kubernetes/manifests/etcd.yaml", "/tmp/etcd-bak.yaml", "etcd"},
    "etcd-healthcheck-client": {"etcd-healthcheck-client", "/etc/kubernetes/manifests/etcd.yaml", "/tmp/etcd-bak.yaml", "etcd"},
    "apiserver-etcd-client":   {"apiserver-etcd-client", "/etc/kubernetes/manifests/kube-apiserver.yaml", "/tmp/kube-apiserver-bak.yaml", "apiserver"},
}

// renewAndCycleOne performs renew + manifest mv-out + sleep + mv-in + active health
// poll for one cert type on one CP. Hard-fails on any sub-step error.
func renewAndCycleOne(node nodes.Node, c certCycle, etcdEndpoint, healthzURL string, logger log.Logger) error {
    // 1. kubeadm certs renew <type>
    if err := node.Command("kubeadm", "certs", "renew", c.certName).Run(); err != nil {
        return errors.Wrapf(err, "kubeadm certs renew %s failed on %s", c.certName, node.String())
    }
    // 2. mv-out
    if err := node.Command("mv", c.manifestPath, c.backupPath).Run(); err != nil {
        return errors.Wrapf(err, "mv out %s failed on %s", c.manifestPath, node.String())
    }
    // 3. wait for kubelet to notice manifest gone
    certRegenSleeper(kubeletFileCheckFrequency + staticPodCycleSafetyMargin)
    // 4. mv-in
    if err := node.Command("mv", c.backupPath, c.manifestPath).Run(); err != nil {
        return errors.Wrapf(err, "mv back %s failed on %s", c.manifestPath, node.String())
    }
    // 5. active health gate (replaces the old static 20s sleep)
    switch c.cycleKind {
    case "etcd":
        if err := etcdHealthChecker(node, etcdEndpoint); err != nil {
            return errors.Wrapf(err, "etcd ready-gate failed on %s after %s renew", node.String(), c.certName)
        }
    case "apiserver":
        if err := apiserverHealthChecker(node, healthzURL); err != nil {
            return errors.Wrapf(err, "apiserver healthz failed on %s after %s renew", node.String(), c.certName)
        }
    }
    logger.V(1).Infof(" ✓ renewed %s on %s, %s pod healthy", c.certName, node.String(), c.cycleKind)
    return nil
}
```

func RegenerateEtcdPeerCertsWholesale(cpNodes []nodes.Node, logger log.Logger) error {

    }

                dumpCertRegenDiagnostics(node, ct, logger)  // see (D)
                return errors.Wrapf(err,
                    "cert regen failed on %s for %s. Cluster state is undefined — delete and recreate the cluster",
                    node.String(), ct)
            }
        }
        // Post-pass verification per CP — kubeadm certs check-expiration.
        if err := verifyCheckExpirationAdvanced(node, certTypes); err != nil {
            dumpCertRegenDiagnostics(node, "post-pass-verify", logger)
            return errors.Wrapf(err,
                "post-pass cert-expiration check failed on %s. Cluster state is undefined — delete and recreate the cluster",
                node.String())
        }
    }
    return nil
}

func dumpCertRegenDiagnostics(node nodes.Node, failedAt string, logger log.Logger) {
    logger.Warnf("=== cert-regen diagnostic dump (failed at: %s on %s) ===", failedAt, node.String())

    // 1. etcdctl member list
    if etcdID := getEtcdContainerID(node); etcdID != "" {
        out, _ := exec.OutputLines(node.Command(
            "crictl", "exec", etcdID, "etcdctl",
            "--cacert=/etc/kubernetes/pki/etcd/ca.crt",
            "--cert=/etc/kubernetes/pki/etcd/peer.crt",
            "--key=/etc/kubernetes/pki/etcd/peer.key",
            "--endpoints=https://127.0.0.1:2379",
            "member", "list", "--write-out=table",
        ))
        logger.Warnf("etcdctl member list:\n%s", strings.Join(out, "\n"))
    }
    // 2. kubeadm certs check-expiration
    out, _ := exec.OutputLines(node.Command("kubeadm", "certs", "check-expiration"))
    logger.Warnf("kubeadm certs check-expiration:\n%s", strings.Join(out, "\n"))
    // 3. last 20 lines of crictl logs kube-apiserver
    if apiID := getApiserverContainerID(node); apiID != "" {
        out, _ := exec.OutputLines(node.Command("crictl", "logs", "--tail", "20", apiID))
        logger.Warnf("kube-apiserver last 20 lines:\n%s", strings.Join(out, "\n"))
    }
    // 4. serial-number table of all certs of interest
    out, _ = exec.OutputLines(node.Command("bash", "-c", `
        for f in /etc/kubernetes/pki/etcd/peer.crt /etc/kubernetes/pki/etcd/server.crt \
                 /etc/kubernetes/pki/etcd/healthcheck-client.crt \
                 /etc/kubernetes/pki/apiserver-etcd-client.crt; do
            echo -n "$f: "
            openssl x509 -noout -serial -in "$f" 2>/dev/null || echo "MISSING"
        done
    `))
    logger.Warnf("cert serials:\n%s", strings.Join(out, "\n"))
}

## 11. Open Questions / Out-of-Scope Flags (do NOT address in 57.3)

### Q1. Requirement ID — new LIFE-13 vs append to LIFE-09?

**Status:** REQUIREMENTS.md currently has `LIFE-09` marked Complete for "HA pause/resume preserves etcd peer connectivity ... cert regen is documented fallback if Docker IPAM is infeasible". The cert-regen fallback path is in-scope of LIFE-09 by its plain wording. Three options for the planner:

- **Option A:** Append a sub-bullet to LIFE-09: "Cert-regen fallback path widened beyond etcd-peer to include all four etcd-adjacent certs; active health-gates replace static sleeps; `--strategy` flag exposes the path for direct invocation."
- **Option B:** New `LIFE-13` (next free ID — LIFE-12 is taken for "kinder dev parity"): "Cert-regen recovery path produces a working HA cluster across IPv4/IPv6/dual-stack after pause+resume."
- **Option C:** Re-open LIFE-09 (mark "In Progress") since its full intent ("cert regen is documented fallback") wasn't actually achieved end-to-end until 57.3.

**Planner's call.** Note: `DIAG-07` (v2.5+ deferred) is adjacent ("Etcd peer-TLS regen via `kubeadm certs renew etcd-peer` as fallback escape hatch (if v2.4 IP-pinning approach proves insufficient in field)") but distinct from 57.3 — DIAG-07 is about an opt-in operator-facing escape hatch; 57.3 is fixing the recovery path that always runs when ip-pin fails.

### Q2. CA bundle rotation behavior of `kubeadm certs renew`

`kubeadm certs renew <type>` is documented as NOT rotating the CA (it signs against the existing CA in `/etc/kubernetes/pki/etcd/ca.crt`). If Plan 01 Task 0's serial-comparison diagnostic shows ca.crt's serial changed across the pause+resume, that is a deeper kubeadm bug and should be filed as a follow-on phase (NOT in 57.3 scope). Diagnostic 1 captures ca.crt's serial precisely so we can rule this out cleanly.

**Do not address in 57.3.**

### Q3. Phase 52 cert-regen redesign

CONTEXT.md `<deferred>` already lists this: "A future phase could explore alternatives — e.g., `kinder pause` capturing the cluster network state and `kinder resume` restoring it exactly so cert rotation is never needed." Out of scope.

### Q4. Inter-CP quorum-health gate

CONTEXT.md `<deferred>` explicitly drops this. If 57.3 UAT shows mid-pass quorum loss, file follow-on phase.

### Q5. `pause-snapshot.json` leaderID may legitimately change post-cert-regen

The doctor check at `resumereadiness.go:231-247` warns "etcd leader changed since pause" when snapshot.leaderID ≠ current leader. After 57.3's recovery path, leader change is **expected** (we restart all etcd pods sequentially). The doctor warning would become a false-positive after a cert-regen-flavored resume. Two options for a future phase: (a) skip the snapshot-leader check when `resume-strategy == cert-regen` was used, or (b) re-capture the snapshot at the end of a successful cert-regen pass. **Out of scope for 57.3.**

### Q6. `etcdctl member list` from a non-leader etcd

The diagnostic dump runs `etcdctl member list` on whichever CP failed. If that CP's etcd is non-functional, the member-list call fails. The dump should `2>&1 || true` each section so a partial dump still produces useful signal. (Already factored into the skeleton in §10D.)

### Q7. Behavior when `kubeadm` is missing or version-mismatched

Kindest/node always ships kubeadm matching the K8s version — this is invariant for kinder. No defensive code needed. Out of scope.
