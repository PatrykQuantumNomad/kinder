## Decisions Made

- **Separate ipMaps per manifest for dual-stack:** `patchEtcdManifestIPs` refactored to accept `etcdIpMap` (IPv4→IPv6 for etcd.yaml) and `apiserverIpMap` (IPv4→new-IPv4 for kube-apiserver.yaml). Root cause: kube-apiserver v1.35 requires `--service-cluster-ip-range[0]` family to match `--advertise-address` family. Dual-stack clusters have IPv4 as the first service CIDR, so kube-apiserver must keep IPv4 advertise-address.
- **IPv6 WAL peer URLs for dual-stack:** `updateEtcdMemberPeerURLs` and `buildNewPeerURL` use `currentIP` (IPv6 for dual-stack) so WAL gets updated to IPv6 peer URLs. Rationale: etcd manifests use IPv6 for `--listen-peer-urls`; WAL must match for peers to connect after restart.
- **etcdHealthGateDeadline 5 minutes:** macOS Docker Desktop etcd restarts under load can take 3-4 minutes. The 60-second deadline caused consistent timeouts.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Dual-stack kube-apiserver manifest corrupted by patchEtcdManifestIPs**
- **Found during:** Task 2 (UAT execution, runs 1-3)
- **Issue:** `patchEtcdManifestIPs` used the same `ipMap` for both etcd.yaml and kube-apiserver.yaml. For dual-stack, `ipMap = {oldIPv4 → newIPv6}` (etcd uses IPv6). This replaced `--advertise-address=oldIPv4` in kube-apiserver.yaml with `--advertise-address=newIPv6`. kube-apiserver v1.35 then rejected startup: `service IP family "10.96.0.0/16" must match public address family "fc00:..."`.
- **Fix:** Refactored `patchEtcdManifestIPs` to accept separate `etcdIpMap` and `apiserverIpMap`. For dual-stack, `apiserverIpMap = {oldIPv4 → newIPv4}`. Non-dual-stack uses the same map for both.
- **Files modified:** `pkg/internal/lifecycle/certregen.go`
- **Commit:** `601ecb4f`

**2. [Rule 1 - Bug] Dual-stack etcd WAL peer URLs set to IPv4 (etcd only listens on IPv6)**
- **Found during:** Task 2 (UAT execution, earlier runs using the wrong binary)
- **Issue:** `updateEtcdMemberPeerURLs` and `buildNewPeerURL` used `extraIP` (IPv4) for dual-stack WAL updates. After simultaneous restart, etcd tried to connect to peers at IPv4 addresses but peers only listen on IPv6 (`--listen-peer-urls` from manifest).
- **Fix:** Both functions now use `currentIP` (IPv6 for dual-stack) as the target peer URL IP.
- **Files modified:** `pkg/internal/lifecycle/certregen.go`
- **Commit:** `601ecb4f`

**3. [Rule 1 - Bug] Dual-stack etcd health check used [::1]:2379 endpoint (etcd listens on 127.0.0.1:2379)**
- **Found during:** Task 2 diagnosis of phase 1.6 `etcdctl member update` timeout
- **Issue:** For dual-stack, `ClusterIPFamily` returns `ipv6=true` (same as IPv6-only), causing the code to use `[::1]:2379` for health checks. But dual-stack etcd manifests have `--listen-client-urls=https://127.0.0.1:2379,...` (IPv4 loopback). etcdctl calls to `[::1]:2379` failed.
- **Fix:** Added `ClusterIPFamilyIsDual` to `lbconfig.go`. For dual-stack (`ipv6=true` AND `isDual=true`), etcd endpoint is `https://127.0.0.1:2379` (not `[::1]:2379`).
- **Files modified:** `pkg/cluster/loadbalancer/lbconfig.go`, `pkg/internal/lifecycle/certregen.go`
- **Commit:** `601ecb4f`
