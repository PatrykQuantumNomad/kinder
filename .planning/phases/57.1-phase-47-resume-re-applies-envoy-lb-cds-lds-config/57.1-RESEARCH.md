## Summary

Phase 57.1 is a surgical regression fix: `Resume()` starts the Envoy LB container but never re-writes its xDS config files (`/home/envoy/cds.yaml`, `/home/envoy/lds.yaml`). The LB entrypoint initializes both files to `resources: []` on every container start (`config.go:167`), so post-resume the LB has zero clusters/zero listeners. The fix adds a Phase 1.25 block in `resume.go` that calls a new shared helper extracted from the create-time inline code.

The create-time atomic-swap is already implemented at `pkg/cluster/internal/create/actions/loadbalancer/loadbalancer.go:93-114` (116 total lines). The refactor collapses the ~60 LOC of inline orchestration in `Execute()` into a helper call. The same helper is then invoked from `resume.go` after the LB start block.

All import-cycle analysis confirms no new cycles: `pkg/cluster/internal/loadbalancer` has zero internal imports and can safely add `pkg/cluster/nodeutils` (which only imports `nodes`, `constants`, `errors`, `exec`). `pkg/internal/lifecycle` can import `pkg/cluster/internal/loadbalancer` — the loadbalancer package does not import lifecycle.

**Primary recommendation:** Extract `WriteDynamicConfig` into `pkg/cluster/internal/loadbalancer/config.go`, refactor `Execute()` to a 10-line call site, add Phase 1.25 in `resume.go` with retry loop + injectable backoff. Write `lbreapply_test.go` using the existing `fakeNode` + `withCmder` + `withReadinessProber` patterns already established in the package.

## Architecture Patterns

### Pattern 1: Phase insertion in Resume()

**What:** Insert a named phase block between Phase 1 (LB start) and Phase 1.5 (ip-pin reconnect).

**Exact insertion point in `pkg/internal/lifecycle/resume.go`:**
- Phase 1 LB start: **lines 317-320**
- Phase 1.5 ip-pin block starts: **line 322**
- Phase 1.25 goes BETWEEN line 321 (closing brace of Phase 1) and line 322 (Phase 1.5 comment)

```go
// Phase 1: LB        ← lines 317-320 (existing)
if lb != nil {
    startNodes([]nodes.Node{lb})
}
// ← INSERT Phase 1.25 HERE

// Phase 1.5: ip-pinned pre-start reconnect.   ← line 322 (existing)
```

The new block:
```go
// Phase 1.25: LB cds/lds reapply (NEW — 57.1).
// Fires immediately after the LB container starts. The LB entrypoint
// resets cds.yaml + lds.yaml to "resources: []" on every start; we
// re-apply the rendered config so Envoy's file-poll picks it up before
// the CPs come up. No-op for single-CP clusters (lb == nil).
if lb != nil {
    if err := reapplyLBConfig(binaryName, lb, cp, opts.Logger); err != nil {
        res := &ResumeResult{
            Cluster:  opts.ClusterName,
            State:    "resumed",
            Nodes:    results,
            Duration: time.Since(t0).Seconds(),
        }
        startErrs = append(startErrs, err)
        return res, aggregateErrors(startErrs)
    }
}
```

**Hard-fail pattern** — exactly mirrors `applyPinnedIPsBeforeCPStart` at lines 327-338 and `RegenerateEtcdPeerCertsWholesale` at lines 370-381: build partial `ResumeResult`, append err to `startErrs`, return early via `aggregateErrors`.

### Pattern 2: WriteDynamicConfig helper extraction

**What:** Move the ~60 LOC inline in `Execute()` (lines 65-113 of `loadbalancer/loadbalancer.go`) into a shared helper in `pkg/cluster/internal/loadbalancer/config.go`.

**Exact current inline code** (`pkg/cluster/internal/create/actions/loadbalancer/loadbalancer.go:65-113`):
```go

controlPlaneNodes, err := nodeutils.SelectNodesByRole(allNodes, constants.ControlPlaneNodeRoleValue)
// ...
for _, n := range controlPlaneNodes {
    backendServers[n.String()] = fmt.Sprintf("%s:%d", n.String(), common.APIServerInternalPort)
}
loadbalancerConfigData := &loadbalancer.ConfigData{
    ControlPlanePort: common.APIServerInternalPort,
```

**After extraction**, `Execute()` becomes ~10 LOC:
```go
func (a *Action) Execute(ctx *actions.ActionContext) error {
    allNodes, err := ctx.Nodes(); if err != nil { return err }
    lb, err := nodeutils.ExternalLoadBalancerNode(allNodes); if err != nil { return err }
    if lb == nil { return nil }
    ctx.Status.Start("Configuring the external load balancer ⚖️")
    defer ctx.Status.End(false)
    cps, err := nodeutils.SelectNodesByRole(allNodes, constants.ControlPlaneNodeRoleValue)
    if err != nil { return err }
    ipv6 := ctx.Config.Networking.IPFamily == config.IPv6Family || ctx.Config.Networking.IPFamily == config.DualStackFamily
    if err := loadbalancer.WriteDynamicConfig(lb, cps, ipv6); err != nil {
        return errors.Wrap(err, "failed to configure external load balancer")
    }
    ctx.Status.End(true)
    return nil
}
```

### Anti-Patterns to Avoid

- **Don't call `defaultCmder` directly from `WriteDynamicConfig` helper** — the helper lives in `pkg/cluster/internal/loadbalancer/` which has no `defaultCmder`. Instead, use `node.Command("sh", "-c", cmd).Run()` which routes through `defaultCmder` in tests via `fakeNode.Command()`.
- **Don't use `docker cp` from host** — CONTEXT explicitly rules this out; use `nodeutils.WriteFile` (which runs `cp /dev/stdin <dest>` inside the container via `node.Command`).
- **Don't add SIGHUP or LB container restart** — file-poll + atomic mv-swap is the locked mechanism.
- **Don't run Phase 1.25 when `lb == nil`** — single-CP clusters have no LB; add the `lb != nil` guard.

## Common Pitfalls

### Pitfall 1: WriteDynamicConfig BackendServers uses CP container NAMES not IPs

**What goes wrong:** Passing IPs instead of names. The CDS template uses `address: {{ $hp.host }}` which goes through Envoy's STRICT_DNS resolver. For kind clusters, the CP container names ARE the DNS hostnames in the Docker network (`kinder-control-plane`, `kinder-control-plane2`, etc.).

**Evidence:** `loadbalancer.go:74`: `backendServers[n.String()] = fmt.Sprintf("%s:%d", n.String(), common.APIServerInternalPort)` — key AND host are both `n.String()` (the container name).

**How to avoid:** In `WriteDynamicConfig`, iterate `cps []nodes.Node` and use `n.String()` for both the map key and the address host.

### Pitfall 2: retry loop must sleep BETWEEN attempts, not before first attempt

**What goes wrong:** Sleeping before the first attempt adds latency with no benefit.

**How to avoid:** Loop structure:
```go
for attempt := 0; attempt < 3; attempt++ {
    if attempt > 0 {
        time.Sleep(defaultLBRetryBackoff)  // sleep ONLY between retries
    }
    if err = loadbalancer.WriteDynamicConfig(lb, cp, ipv6); err == nil {
        break
    }
    lastErr = err
}
```

### Pitfall 3: IPv6 discovery docker inspect format parsing

**What goes wrong:** `{{json .NetworkSettings.Networks}}` returns a JSON object with network names as keys. Must extract the first key. If the LB is attached to multiple networks (e.g. bridge + kind-net), the "first" key may be "bridge" not the kind network.

**Mitigation per CONTEXT.md:** Take first network — this is sufficient because kind creates a dedicated network and the LB is primarily attached to it. Log V(1) if parsing fails and default to IPv4.

### Pitfall 4: lbreapply_test.go MUST NOT use t.Parallel() if it mutates defaultCmder

**What goes wrong:** Package-level `defaultCmder` mutation races with parallel tests.

**Evidence:** `resume_test.go:783`: "MUST NOT use t.Parallel() — they mutate shared package-level globals."

**How to avoid:** Every test in `lbreapply_test.go` that calls `withCmder(t, ...)` must NOT call `t.Parallel()`.

### Pitfall 5: config_test.go WriteDynamicConfig tests require a real nodes.Node or mock

**What goes wrong:** `WriteDynamicConfig` takes `nodes.Node` — config_test.go is in `package loadbalancer` (not lifecycle) and has no access to `fakeNode`. It will need its own minimal `nodes.Node` mock.

**How to avoid:** Define a minimal `testNode` (or `fakeNode`) in `config_test.go` that implements `nodes.Node` and captures command calls — similar to the pattern in `state_test.go`. The `Command` method should record invocations and return a configurable error.

## Tensions / Open Questions for the Planner

### Tension 1: WriteDynamicConfig node parameter — which Node type?

**Claim in CONTEXT.md:** `WriteDynamicConfig(node nodes.Node, cps []nodes.Node, ipv6 bool) error`

**Verified:** `nodes.Node` is `sigs.k8s.io/kind/pkg/cluster/nodes.Node` (defined in `pkg/cluster/nodes/types.go:26`). This is the correct type. No conflict. The `nodeutils.WriteFile` function also takes `nodes.Node`.

**Resolution: No tension. Use `nodes.Node` exactly as specified.**

### Tension 2: WriteDynamicConfig needs `node.Command("sh", "-c", cmd).Run()` — how does this get tested?

**Issue:** `WriteDynamicConfig` lives in `pkg/cluster/internal/loadbalancer/` which has no `defaultCmder` injectable. The `node.Command()` call goes directly to the real runtime.

**Resolution:** In `config_test.go`, define a `testNode` struct that implements `nodes.Node` with a `Command` method that returns a scripted `fakeCmd`. Because `WriteDynamicConfig` takes `node nodes.Node`, passing `&testNode{...}` is sufficient. No `defaultCmder` injection is needed in the loadbalancer package — the node IS the injectable.

**Planner action:** Ensure `config_test.go` defines a local minimal `testNode` that records `Command()` calls and returns configurable errors.

### Tension 3: IPv6 discovery error — what should `reapplyLBConfig` do if docker inspect fails?

**CONTEXT.md Claude's Discretion:** "sensible default is to assume IPv4 and log a V(1) info line."

**Recommendation:** On `docker inspect` failure for network name or `EnableIPv6`, log `opts.Logger.V(1).Infof(...)` and proceed with `ipv6 = false`. This is consistent with the "tolerates not-yet-running upstream backends" design — Envoy doesn't need to be running when config is written.

**Planner action:** Document this as the explicit default in lbreapply.go with a code comment.

### Tension 4: Should `reapplyLBConfig` live in lbreapply.go or resume.go?

**Recommendation:** Separate `lbreapply.go` file. Mirrors `certregen.go` and `ippin.go` pattern — Phase-specific helpers live in their own file, `resume.go` only contains the orchestration function. This makes the file smaller and easier to unit test in isolation.

**Planner action:** Create `pkg/internal/lifecycle/lbreapply.go` as the home for `reapplyLBConfig`, `defaultLBRetryBackoff`, and any IPv6-discovery helper.
