# Phase 57.1: Phase 47 Resume re-applies Envoy LB cds/lds config - Context

**Gathered:** 2026-05-13
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix the Phase 47 ↔ Phase 51 regression: `lifecycle.Resume()` starts the Envoy LB container in the documented quorum-safe ordering but never re-applies the LB's dynamic xDS config (`/home/envoy/cds.yaml`, `/home/envoy/lds.yaml`). The LB container's hardcoded entrypoint resets both files to `resources: []` on every start, so after `kinder pause` + `kinder resume` the LB has zero clusters/zero listeners and host `kubectl` gets `EOF`.

The fix mirrors the create-time atomic-swap path (template render → `nodeutils.WriteFile` to `.tmp` → `mv` swap → Envoy file-poll picks it up). Add a single new code path inside `Resume()` that fires after the LB container starts. Refactor the create-time action to share the helper so there's a single atomic-swap implementation.

Out of scope: SIGHUP reload, LB container restart, `docker cp` from host, new doctor checks, new LB health-watch commands.

</domain>

<decisions>
## Implementation Decisions

### Trigger ordering in Resume()
- **Insertion point: Phase 1.25 — immediately after LB container start, BEFORE CP container start** (no-op if `nodeutils.ExternalLoadBalancerNode(allNodes)` returns nil, per ROADMAP SC3).
- Symmetric with create-time (which writes cds/lds while CPs are still starting). Envoy file-polls; tolerates not-yet-running upstream backends.
- **The reapply has NO functional dependency on Phase 1.5 (ip-pin) or Phase 4.5 (cert-regen).** Cds/lds encode CP container *names* (e.g. `kinder-control-plane:6443`, per `loadbalancer.go:73-75`), not IPs. Container names are stable across pause/resume; certs live on CPs, not in the LB; IPs don't appear in cds/lds at all. The ROADMAP RISK NOTE's "AFTER cert-regen/ip-pin finishes" guidance was caution, not a derived constraint.
- **Insertion order in Resume() (after this fix):**
  ```
  Phase 1:    LB start
  Phase 1.25: ★ LB cds/lds reapply (NEW)
  Phase 1.5:  ip-pinned CP --ip reconnect
  Phase 2:    CP start
  Phase 3:    HA readiness hook
  Phase 4:    workers start
  Phase 4.5:  cert-regen (reactive)
              kubectl readiness probe
  ```

### Failure handling
- **Retry 3x with 1s backoff, then HARD-FAIL Resume()** (return error; downstream phases — ip-pin, CP start, HA hook, workers, cert-regen, readiness probe — never run).
- Matches the existing `applyPinnedIPsBeforeCPStart` / `RegenerateEtcdPeerCertsWholesale` hard-halt pattern (Resume() guarantees cluster reachability or fails loudly).
- Backoff is injectable via package-level `var defaultLBRetryBackoff = 1 * time.Second` (test-overridable to 0; matches the established `ipamProbeCmder` / `certRegenSleeper` injection pattern in this codebase).
- Error message should follow the existing wording style: `"LB reapply failed after 3 attempts: <wrapped err>; re-run kinder resume to retry"`. Final wording locked during planning.

### Code reuse: shared `WriteDynamicConfig` helper
- **Extract a new shared helper in `pkg/cluster/internal/loadbalancer/`** (most likely `config.go`):
  ```go
  func WriteDynamicConfig(node nodes.Node, cps []nodes.Node, ipv6 bool) error
  ```
- The helper owns: build `BackendServers` map, render LDS + CDS templates via existing `loadbalancer.Config()`, `nodeutils.WriteFile` to `.tmp` paths (`ProxyConfigPathLDS + ".tmp"`, `ProxyConfigPathCDS + ".tmp"`), shell-exec the `chmod 666 && mv && mv` atomic swap.
- **Refactor `pkg/cluster/internal/create/actions/loadbalancer/loadbalancer.go` `Execute()` to call the helper** — the existing ~70 LOC of inline orchestration collapses to ~10 LOC of (`ExternalLoadBalancerNode`, `SelectNodesByRole`, IPv6 from `ctx.Config.Networking.IPFamily`, helper call, status reporting).
- Resume calls the same helper from `pkg/internal/lifecycle/` after discovering IPv6 via docker network inspect (see below).
- **Blast radius is acceptable:** two files in two packages plus tests. Worth the larger blast radius for single source of truth on the atomic-swap mechanism — a future Envoy template change must not silently diverge between create and resume.

### IPv6 / IPFamily discovery in Resume()
- **Discover via docker network inspect on the LB's attached network:**
  1. `docker inspect <lb> --format '{{json .NetworkSettings.Networks}}'` → extract first network name (the kind network)
  2. `docker network inspect <network-name> --format '{{.EnableIPv6}}'` → `"true"` / `"false"`
  3. `ipv6 = strings.TrimSpace(out) == "true"`
- No new label, no bootstrap-config parsing, no create-time change for this discovery (the create-time change is only the helper extraction).
- This passes the `ipv6` flag into `WriteDynamicConfig`, which feeds it into `loadbalancer.ConfigData{IPv6: ipv6}`. The template controls LDS bind (`::` vs `0.0.0.0`) and CDS DNS lookup family (`AUTO` vs `V4_PREFERRED`).

### Test coverage: comprehensive
- **In `pkg/cluster/internal/loadbalancer/config_test.go` (additions for the new helper):**
  - Happy path IPv4 (3 CPs) — renders LDS/CDS with `0.0.0.0` bind + `V4_PREFERRED` lookup
  - Happy path IPv6 (3 CPs) — renders LDS/CDS with `::` bind + `AUTO` lookup
  - Error: `WriteFile` returns error → helper returns wrapped error
  - Error: `mv` shell-swap returns error → helper returns wrapped error
- **In `pkg/internal/lifecycle/lbreapply_test.go` (new file):**
  - SC5: FakeNode LB + 3 CPs → cds.yaml non-empty AND contains all 3 CP container names; lds.yaml non-empty
  - SC3: no LB in allNodes → reapply is a no-op (returns nil; no docker calls)
  - Retry success on attempt 2 (first attempt's cmder fails, second succeeds → helper returns nil)
  - Retry exhausted (3 failures → Resume() returns error; downstream phases not reached)
  - IPv6 detection: mocked `docker network inspect` returns `EnableIPv6=true` → template uses IPv6 bind
  - IPv4 detection: mocked `docker network inspect` returns `EnableIPv6=false` → template uses IPv4 bind
- **Retry test isolation: injectable backoff** via package-level `var defaultLBRetryBackoff = 1 * time.Second`. Tests override to 0 with deferred restore. Total retry-exhausted test runs in <50ms.

### Claude's Discretion
- Exact helper name (`WriteDynamicConfig` vs `ReapplyDynamicConfig` vs `WriteCDSAndLDS` — pick the name that reads best alongside `GenerateBootstrapCommand`).
- Final error message wording for the hard-fail path (style match with `applyPinnedIPsBeforeCPStart` "cluster state is undefined" tone vs lighter "re-run kinder resume to retry" tone).
- How the IPv6 discovery error path behaves (e.g. docker inspect fails) — sensible default is to assume IPv4 and log a V(1) info line; planner can re-justify if a different default is safer.
- Whether the `ResumeReadinessHook` pattern (package-level `var` overridable in tests) is mirrored for the reapply helper, or whether tests inject via the existing `defaultCmder` cmder pattern. Planner picks based on what reads cleanest.
- Per-file location split inside the lifecycle package (separate `lbreapply.go` file vs. inlining into `resume.go`).

</decisions>

<specifics>
## Specific Ideas

- **Mirror the create-time atomic-swap shell command verbatim** (`loadbalancer.go:106-110`):
  ```
  chmod 666 <tmpLDS> <tmpCDS> && mv <tmpLDS> <ProxyConfigPathLDS> && mv <tmpCDS> <ProxyConfigPathCDS>
  ```
  Single sh `-c` invocation. No SIGHUP, no LB restart, no docker cp from host.

- **Reference: the bug's discovery path (Phase 58 UAT test_09, 2026-05-13).** Symptom: host `kubectl` returns `Unable to connect to the server: EOF`; `curl https://localhost:6443/healthz` from inside CP1 returns `ok`; `docker exec <lb> cat /home/envoy/cds.yaml` shows `resources: []`. Phase 58 UAT script `hack/uat-47-ha-smoke.sh` test_09 is the end-to-end regression gate after this fix lands (per ROADMAP SC6) — no further script changes required.

- **Git archaeology pointer for the planner:**
  - 47-03 commit `50c686aa` — original Resume() pre-Envoy
  - 51-01 commit `4267886a` — added atomic-swap to create-time only
  - 52-03 commit `c38bbdf1` — added HA strategy dispatch, but no LB reapply

</specifics>

<deferred>
## Deferred Ideas

- **LB health-watch / health-check doctor check** — a `kinder doctor cluster-lb-health` that verifies cds/lds are non-empty and Envoy is forwarding. Useful follow-up, but out of scope for this regression fix. Add to backlog as a potential v2.5 diagnostic.
- **Label on LB recording IPFamily at create-time** (`io.x-k8s.kind.lb-ipv6=true|false`) — explicit alternative to network inspection. Not adopted here (docker network inspect is sufficient and avoids create-time churn) but worth considering if IPFamily ever becomes more complex (e.g. v6-only paths or per-CP IP family).
- **SIGHUP-based reload alternative** — Envoy supports SIGHUP for config reload, but the existing create-time path deliberately uses file-poll + atomic mv-swap. This fix preserves that contract. Revisiting is its own discussion.
- **Pre-resume LB config snapshot/restore** — instead of regenerating from CP names, snapshot cds/lds before pause and restore on resume. Adds state-tracking complexity for marginal benefit (regenerating is deterministic). Not adopted.

</deferred>
