## Deviations from Plan

### Documented findings (not auto-fixes)

**1. [SC4 structural caveat] macOS Docker Desktop port-mapping topology**
- **Found during:** test_11 forensic inspection
- **Issue:** Plan 02's SC4 said the IPv6 host-kubectl path "verifies ipv4_compat actually lets the host kubectl reach an IPv6 listener". On macOS Docker Desktop, Docker Desktop's port-mapping topology mirrors the cluster's IPFamily — there is **no** IPv4 port-mapping for an IPv6 cluster's LB (IPv6 cluster's LB only exposes `[::1]:<port>->6443/tcp`). The host-via-IPv4 portion of SC4 is therefore structurally unreachable on this host.
- **Resolution:** The listener-fix portion of SC4 is verified at file level (test_08/10 PASS). The host-via-IPv4 portion is documented in UAT.md as a structural caveat, flagged for the verifier. No SC wording revision filed in this plan (roadmap-author scope).
- **Files affected:** Documentation only — UAT.md "SC4 Structural Caveat" section.

**2. [Out-of-scope downstream defect] IPv6 HA cluster cert-regen recovery**
- **Found during:** test_11 forensic inspection (post-failure live diagnostics on the still-running `uat-572-ipv6` cluster)
- **Issue:** After Phase 52's cert-regen fires on the IPv6 HA cluster during resume, kube-apiserver crash-loops because it can't TLS-handshake to etcd on `[::1]:2379`. Root cause is either an incomplete etcd `server.crt` SAN list (missing `[::1]`) or an etcd peer re-coordination issue post-cert-regen. The failing layer is upstream of the LB and untouched by Phase 57.2's edits — explicitly out of scope.
- **Resolution:** Documented in UAT.md "Forensic Deep-Dive" with the full diagnostic command sequence. Filed for a new follow-up phase (suggested: Phase 57.3 or Phase 52.1). Orchestrator will route the new phase via `/gsd:insert-phase`. ROADMAP.md and REQUIREMENTS.md updates are explicitly out of scope for this plan.
- **Files affected:** Documentation only — UAT.md "Forensic Deep-Dive" section + STATE.md Blockers section.
