# Phase 57.2 Plan 01: Fix discoverLBIPv6 — derive IPv6 mode from cluster IPFamily Summary

**Replaces the broken docker-network probe with a cluster-authoritative ip-family label read via the new loadbalancer.ClusterIPFamily helper; injects the label on every container in all 3 providers; adds Envoy `ipv4_compat: true` to the IPv6/dual listener so macOS Docker Desktop's IPv4 port-mapping reaches dual-stack clusters.**

## Accomplishments

- **Phase 58 UAT regression closed.** The bug-of-record (`uat-58-01` 2026-05-13 host-kubectl TLS-EOF) is now caught by the named regression test `TestClusterIPFamily_MacOSDualStackNetwork_IPv4Cluster` which asserts the helper returns `false` for IPv4 clusters AND never invokes `docker network inspect`. Phase 58 is unblocked.
- **discoverLBIPv6 entirely removed.** Zero `grep -rn discoverLBIPv6 pkg/` hits after Task 2 (the function definition, the call site, and all doc-comment back-references were scrubbed).
- **Single source of truth.** Both create-time (`cfg.Networking.IPFamily` directly) and resume-time (`loadbalancer.ClusterIPFamily` reading the label) produce the same `ipv6 bool` because the label is the deterministic forward map of `cfg.Networking.IPFamily` via `IPFamilyLabelValue` — agreement is architectural, not behavioral.
- **Listener template fix landed atomically.** `ProxyLDSConfigTemplate` adds `ipv4_compat: true` under the IPv6/dual branch; IPv4 stays bare `0.0.0.0`. Closes both the resume regression AND the latent create-time bug (nobody had run macOS Docker Desktop with a dual-stack cluster + host kubectl before).
- **6-fixture FakeNode matrix.** `TestClusterIPFamily_LabelMatrix` enumerates `{ipv4, ipv6, dual}` × `{macOS-style dual-stack network, linux-style IPv4-only network}` and all 6 sub-tests pass with `sawNetworkInspect == false` — the dimensional coverage CONTEXT.md required.

## Decisions Made

- **Use `withCmder` to swap BOTH cmders rather than per-test wiring** (deviation from plan; see below). Plan said the lifecycle test rewrite "MUST compile" but didn't anticipate the existing 20+ resume tests would all hit the same gap. The keystone swap in `withCmder` is the smallest possible change that keeps the existing test surface working.
- **Default to `"ipv4\n"` in `startCallRecorder` label-inspect handler** rather than per-test label opt-in. No existing resume test exercises an IPv6/dual cluster through the recorder; future tests that need to can extend the recorder with an explicit `ipFamilyLabel` field.
- **`gofmt -w` ran on the staging branch** to normalize indentation and import block formatting. Did not change semantics. Touched files: `lbconfig.go`, `lbconfig_test.go`, `config_test.go`, `state_test.go`.
