## Summary

Phase 57.2 fixes the `discoverLBIPv6` function introduced in Phase 57.1 that mis-classifies IPv4 clusters as IPv6 on macOS Docker Desktop. The root cause: `discoverLBIPv6` (`pkg/internal/lifecycle/lbreapply.go:59-90`) probes `docker network inspect --format '{{.EnableIPv6}}'`, which is always `true` on macOS Docker Desktop's default `kind` network — even for IPv4-only clusters. The fix stamps an authoritative `io.x-k8s.kinder.ip-family` label on every container at create-time, and reads that label at resume-time via a shared helper `clusterIPFamily(node) (bool, error)` living in `pkg/cluster/loadbalancer/`.

The phase has three concurrent concerns:
1. **Label write-side**: inject `--label io.x-k8s.kinder.ip-family=<ipv4|ipv6|dual>` into `runArgsForLoadBalancer` and `runArgsForNode` in all three providers (docker, podman, nerdctl).
2. **Label read-side + helper**: replace `discoverLBIPv6` in `lbreapply.go` with a call to `clusterIPFamily(lb)` that reads the label via `docker inspect --format '{{index .Config.Labels "io.x-k8s.kinder.ip-family"}}' <lb>`.
3. **Listener template fix**: add `ipv4_compat: true` to the IPv6/dual branch of `ProxyLDSConfigTemplate` in `pkg/cluster/internal/loadbalancer/config.go:70`.

**Primary recommendation:** Inject the ip-family label in `runArgsForLoadBalancer` and `runArgsForNode` in all three provider create files (docker/podman/nerdctl), add a new constant to `pkg/cluster/constants/constants.go`, implement `clusterIPFamily` in `pkg/cluster/loadbalancer/lbconfig.go`, and update `reapplyLBConfig` to call it instead of `discoverLBIPv6`.

## Architecture Patterns

### Pattern 1: Phase 52 Resume-Strategy Label (the closest analog)

**Confidence: HIGH** — verified from source.

The resume-strategy label `io.x-k8s.kinder.resume-strategy` is defined in `pkg/cluster/constants/constants.go:29` as `const ResumeStrategyLabel = "io.x-k8s.kinder.resume-strategy"`. It is consumed:
- **Write-side**: injected via `--label` in `planCreation()` closures for CP containers only, in both docker (`pkg/cluster/internal/providers/docker/create.go:124-128`) and podman (`pkg/cluster/internal/providers/podman/provision.go:117-122`) providers. The nerdctl provider has no strategy injection currently.
- **Read-side**: read at resume via `docker inspect --format '{{index .Config.Labels "io.x-k8s.kinder.resume-strategy"}}' <container>` in `resume.go:121`.

The ip-family label follows the same pattern, with the difference that it must be injected on **all container types** (LB + CP + workers), not just CPs.

### Pattern 2: Label injection technique

**Confidence: HIGH** — verified from `pkg/cluster/internal/providers/docker/create.go:124-128`.

Labels are injected by inserting `["--label", "key=value"]` immediately before the image in the `args` slice, because `docker run` / `podman run` / `nerdctl run` require `--label` before the image name (the image is always the last element in `runArgsForNode` / `runArgsForLoadBalancer`). Exact pattern:

```go
labelArgs := []string{"--label", fmt.Sprintf("%s=%s", constants.ResumeStrategyLabel, strategy)}
args = append(args[:len(args)-1], append(labelArgs, args[len(args)-1])...)
```

For the ip-family label, the same technique applies. Since it is cluster-wide (not per-node), the label value is computed once from `cfg.Networking.IPFamily` and injected in both `runArgsForLoadBalancer` and `runArgsForNode`.

### Pattern 3: Label read at resume-time

**Confidence: HIGH** — verified from `resume.go:119-128`.

```go
func readResumeStrategy(binaryName string, cpNodes []nodes.Node) string {
    bootstrap := cpNodes[0].String()
    lines, err := exec.OutputLines(defaultCmder(binaryName,
        "inspect",
        "--format", `{{index .Config.Labels "`+ResumeStrategyLabel+`"}}`,
        bootstrap,
    ))
    ...
}
```

The `clusterIPFamily` helper reads `io.x-k8s.kinder.ip-family` from the LB container (or the bootstrap CP for single-CP clusters) in the same format. Since the LB is always present in HA clusters (the only case where `reapplyLBConfig` runs), reading from `lb` is the right choice. Fail-loud when label absent (contrast with `readResumeStrategy` which silently falls back to `""`; ip-family must fail-loud per CONTEXT.md decision).

### Pattern 4: `clusterIPFamily` helper home and signature

**Confidence: HIGH** — verified from `pkg/cluster/loadbalancer/lbconfig.go`.

`pkg/cluster/loadbalancer/` currently contains only `lbconfig.go`, which re-exports `WriteDynamicConfig` from `pkg/cluster/internal/loadbalancer`. The helper lives here because `pkg/internal/lifecycle` cannot import `pkg/cluster/internal/loadbalancer` directly (different internal subtrees violate Go's internal package rule). The helper signature:

```go
// ClusterIPFamily reads the io.x-k8s.kinder.ip-family label from node and
// returns (true, nil) for IPv6/dual, (false, nil) for IPv4.
// Returns an error if the label is absent or unrecognized — no fallback.
func ClusterIPFamily(binaryName string, node nodes.Node) (bool, error)
```

Both create-time (the loadbalancer action at `pkg/cluster/internal/create/actions/loadbalancer/loadbalancer.go:70-71`) and resume-time (`reapplyLBConfig`) consume `WriteDynamicConfig`. Create-time already has `ctx.Config.Networking.IPFamily` — it does NOT call the helper to derive IPv6; it derives it inline. The helper is only needed on the **resume side** to replace `discoverLBIPv6`. Create-time reads from config; resume-time reads from the label via the helper. The architectural guarantee is that both paths produce the same `ipv6 bool` because the label faithfully encodes the original `cfg.Networking.IPFamily`.

### Pattern 5: Envoy `ipv4_compat` in `ProxyLDSConfigTemplate`

**Confidence: HIGH** — verified from Envoy v3 official docs + config.go source.

Current template (`pkg/cluster/internal/loadbalancer/config.go:64-79`):

```yaml
resources:
- "@type": type.googleapis.com/envoy.config.listener.v3.Listener
  name: listener_apiserver
  address:
    socket_address:
      address: {{ if .IPv6 }}"::"{{ else }}"0.0.0.0"{{ end }}
      port_value: {{ .ControlPlanePort }}
```

Required change — add `ipv4_compat: true` under `socket_address` for IPv6/dual:

```yaml
      address: {{ if .IPv6 }}"::"{{ else }}"0.0.0.0"{{ end }}
      port_value: {{ .ControlPlanePort }}
      {{ if .IPv6 }}ipv4_compat: true{{ end }}
```

Envoy's `SocketAddress.ipv4_compat` (boolean, underscore-delimited) is documented at https://www.envoyproxy.io/docs/envoy/latest/api-v3/config/core/v3/address.proto: "When binding to `::` will allow both IPv4 and IPv6 connections, with peer IPv4 addresses mapped into IPv6 space as `::FFFF:<IPv4-address>`." Valid on listener `socket_address`; has no effect when `address` is `0.0.0.0`.

### Pattern 6: Nerdctl provider label injection

**Confidence: HIGH** — verified from source.

The nerdctl `planCreation` signature is `func planCreation(cfg *config.Cluster, networkName, binaryName string)` — it does NOT currently accept a `strategy` parameter (`pkg/cluster/internal/providers/nerdctl/create.go:36`). Resume-strategy is not injected for nerdctl (nerdctl doesn't support IP pinning). For ip-family, the label value is derived from `cfg.Networking.IPFamily` which is available in the closure — no signature change needed. The injection can be done inside `runArgsForLoadBalancer` and `runArgsForNode` directly, accepting `ipFamily config.ClusterIPFamily` (or just the label value string) as an additional parameter.

### 2. Container labeling mechanics

**Confidence: HIGH** — verified from source.

Labels are set at container creation time only (Docker/Podman API limitation — no post-creation label update). They are passed as `--label key=value` args in the `docker run` / `podman run` / `nerdctl run` command. All three providers use the same arg-list construction pattern. Reading them at resume-time uses `docker inspect --format '{{index .Config.Labels "key"}}' <container>`.

The IPFamily value-to-label-string mapping:
- `config.IPv4Family` ("ipv4") → `"ipv4"`
- `config.IPv6Family` ("ipv6") → `"ipv6"`
- `config.DualStackFamily` ("dual") → `"dual"`
- Default (empty, treated as IPv4) → `"ipv4"` (defensive)

### 4. Shared helper API and node type compatibility

**Confidence: HIGH** — verified from `nodes/types.go` and `lbconfig.go`.

`nodes.Node` is an interface (`pkg/cluster/nodes/types.go:26-40`) with methods: `String() string`, `Role() (string, error)`, `IP() (string, string, error)`, `SerialLogs(io.Writer) error`, plus `exec.Cmder` (i.e., `Command(string, ...string) exec.Cmd` and `CommandContext(context.Context, string, ...string) exec.Cmd`).

Both create-time (action context has `loadBalancerNode nodes.Node` from `nodeutils.ExternalLoadBalancerNode(allNodes)`) and resume-time (`lb nodes.Node` from `ClassifyNodes(allNodes)`) use the same `nodes.Node` interface. No adapter needed.

The `ClusterIPFamily` helper takes only `binaryName string` and `node nodes.Node` — it calls `binaryName inspect --format '{{index .Config.Labels "io.x-k8s.kinder.ip-family"}}' <node.String()>` via `exec.OutputLines(exec.Command(...))`. It does NOT use `node.Command()` because label inspection is a host-side docker call, not an exec into the container.

**Important:** The helper uses the package-level `exec.Command` directly (or a testable indirection like the `defaultCmder` var pattern). If the helper lives in `pkg/cluster/loadbalancer/lbconfig.go`, which is a public package (not internal), it cannot use the lifecycle package's `defaultCmder`. Options:
  - Add its own injectable `Cmder` var in `lbconfig.go` (mirrors lifecycle's pattern)
  - Accept the cmder as a parameter
  - Use `exec.Command` directly (not testable without real docker)
  
The cleanest match to the Phase 52/57.1 pattern: add `var clusterIPFamilyCmder = exec.Command` in `lbconfig.go` and use it for the helper — allows test injection.

### 5. Envoy template behavior and `ipv4_compat`

**Confidence: HIGH** — verified from official Envoy v3 docs.

Current `ProxyLDSConfigTemplate` IPv6/dual branch renders:
```yaml
      address: "::"
      port_value: 6443
```

Envoy v3 `SocketAddress.ipv4_compat` (field `ipv4_compat`, boolean, underscore) is a valid field on `config.core.v3.SocketAddress`. When `address: "::"` and `ipv4_compat: true`, Envoy binds to `::` and accepts both IPv4 and IPv6 connections (IPv4 mapped as `::FFFF:<addr>`). Without `ipv4_compat: true`, the `::` listener is IPv6-only — connections from `127.0.0.1:PORT` (Docker Desktop's host port-mapping, which is IPv4) fail with TLS EOF.

The required template change — add `ipv4_compat: true` conditionally on `.IPv6`:

```yaml
    socket_address:
      address: {{ if .IPv6 }}"::"{{ else }}"0.0.0.0"{{ end }}
      port_value: {{ .ControlPlanePort }}
      {{ if .IPv6 }}ipv4_compat: true{{ end }}
```

Alternatively (and slightly cleaner for the YAML indentation):
```
      address: {{ if .IPv6 }}"::"{{ else }}"0.0.0.0"{{ end }}
      port_value: {{ .ControlPlanePort }}
{{- if .IPv6 }}
      ipv4_compat: true
{{- end }}
```

No other listener fields need touching. The admin address (`0.0.0.0:10000` in `DynamicFilesystemConfigTemplate`) is not affected because it's the Envoy admin interface, not the API server listener.

The existing test `TestConfigLDSIPv6` at `config_test.go:148` asserts `"::"` is present for IPv6 mode. Phase 57.2 adds a new assertion: also check `ipv4_compat: true` is present for IPv6/dual. For IPv4, assert `ipv4_compat` is NOT present.

### 8. Pitfalls and unknowns

**Confidence: HIGH** — all verified from source.

**P1 — `discoverLBIPv6` has exactly one call site.**
Confirmed: `lbreapply.go:101` is the only production call. No other file calls it (grep confirmed). Safe to delete the function entirely with no fallback.

**P2 — nerdctl provider does NOT inject resume-strategy label.**
`planCreation` in `nerdctl/create.go:36` has no `strategy` param and no label injection. For ip-family, since it derives from `cfg.Networking.IPFamily` (not a probe), it can be injected independently of the nerdctl strategy gap. The label injection in nerdctl is straightforward — add it into `runArgsForLoadBalancer` and `runArgsForNode` directly.

**P3 — `clusterIPFamily` helper in the public `pkg/cluster/loadbalancer/` package cannot use `pkg/internal/lifecycle`'s `defaultCmder`.**
Must add its own injectable cmder var (e.g., `var defaultClusterIPFamilyCmder = exec.Command`) and use it for testing. Tests in `pkg/cluster/loadbalancer/` will swap this var. Tests in `pkg/internal/lifecycle/` continue to use the lifecycle package's `defaultCmder` for the full `reapplyLBConfig` integration.

**P4 — Label absent on resume → fail-loud.**
The CONTEXT.md decision requires: if the `ip-family` label is missing, fail with "delete and recreate the cluster" guidance. The error from `ClusterIPFamily` must include this text. Do NOT return a bool default — fail loudly. This is different from `readResumeStrategy` which returns `""` for absent labels (legacy path). There is no legacy path for ip-family.

**P5 — `runArgsForLoadBalancer` currently does not accept an ipFamily parameter.**
All three providers' `runArgsForLoadBalancer` only take `(cfg *config.Cluster, name string, args []string)`. The `cfg.Networking.IPFamily` is already available in `cfg`. The label value computation can be done inside `runArgsForLoadBalancer` without changing the call signature — it reads `cfg.Networking.IPFamily` directly. Same for `runArgsForNode` which takes `(node *config.Node, clusterIPFamily config.ClusterIPFamily, name string, args []string)` — the label value comes from `clusterIPFamily`.

**P6 — `ipv4_compat: true` should ONLY appear in the IPv6/dual branch.**
Template Go conditional must be strict: `{{if .IPv6}}ipv4_compat: true{{end}}`. IPv4-only listeners (`0.0.0.0`) must NOT have `ipv4_compat`. The assertion in `config_test.go` must check this explicitly (IPv4 rendered output must not contain `ipv4_compat`).

**P7 — Phase 52 stamped resume-strategy label on CPs only; ip-family stamps on ALL containers including LB.**
The current CP-only strategy label injection is in the control-plane closure at `create.go:117-129`. For ip-family, the most pragmatic approach: inject in `runArgsForLoadBalancer` (for LB) and in both CP and worker closures (for all nodes). The `clusterIPFamily` helper reads from the LB container at resume-time, so the LB label is the critical one. Worker and CP labels are "nice to have" for diagnostics but also cheap to stamp.

**P8 — `fakeNode.Command()` routes through `defaultCmder`.**
In `state_test.go:43`, `fakeNode.Command(c, a...)` delegates to `defaultCmder(c, a...)`. This means when `ClusterIPFamily` calls `exec.Command(binaryName, "inspect", ...)` via `defaultClusterIPFamilyCmder`, and if tests need to mock this from the lifecycle package test, they must swap both `defaultCmder` (lifecycle) and `defaultClusterIPFamilyCmder` (loadbalancer package). The cleanest solution: have `ClusterIPFamily` accept an optional `cmder` func via a package var in `lbconfig.go`, and in lifecycle tests have `newLBCmder` handle the label-inspect case.

**P9 — `createContainerFuncs` runs concurrently for docker/podman.**
Phase 52 verifies this doesn't cause issues (the strategy label is per-closure-captured and immutable). The ip-family label value is also captured once per cluster config and immutable — no concurrency concern.

## Code Examples

### Computing ip-family label value (create-time)

```go
// IPFamilyLabelValue converts a ClusterIPFamily to the label string value.
// ipv4 → "ipv4", ipv6 → "ipv6", dual → "dual", default → "ipv4".
func ipFamilyLabelValue(f config.ClusterIPFamily) string {
    switch f {
    case config.IPv6Family:
        return "ipv6"
```

### `ClusterIPFamily` helper in `pkg/cluster/loadbalancer/lbconfig.go`

```go
var defaultClusterIPFamilyCmder = exec.Command

// ClusterIPFamily reads the io.x-k8s.kinder.ip-family label from node
// and returns (true, nil) for ipv6 or dual, (false, nil) for ipv4.
// Returns an error if the label is absent or has an unrecognized value —
// no fallback; caller must fail-loud with "delete and recreate" guidance.
func ClusterIPFamily(binaryName string, node nodes.Node) (bool, error) {
    cmd := defaultClusterIPFamilyCmder(binaryName,
        "inspect", "--format",
        `{{index .Config.Labels "`+constants.IPFamilyLabel+`"}}`,
        node.String(),
    )
    var out strings.Builder
    cmd.SetStdout(&out)
    if err := cmd.Run(); err != nil {
        return false, errors.Wrapf(err, "ClusterIPFamily: docker inspect failed for %s", node.String())
    }
    val := strings.TrimSpace(out.String())
    switch val {
    case "ipv6", "dual":
        return true, nil
    case "ipv4":
        return false, nil
    case "":
        return false, errors.Errorf(
            "ClusterIPFamily: ip-family label absent on %s — delete and recreate the cluster",
            node.String(),
        )
    default:
        return false, errors.Errorf(
            "ClusterIPFamily: unrecognized ip-family label value %q on %s — delete and recreate the cluster",
            val, node.String(),
        )
    }
}
```
