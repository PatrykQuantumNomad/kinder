<objective>
Fix DIAG-05 by adding an inline LB-role guard to `realListNodes` in `pkg/internal/doctor/clusterskew.go` so external-load-balancer containers (haproxy/envoy — which have no `/kind/version` file) are not subjected to the `cat /kind/version` exec, eliminating the false-positive version-skew warning on HA clusters. Add the same defensive guard for `external-etcd` to future-proof.

Purpose: ROADMAP Phase 57 SC1 — "`kinder doctor cluster-node-skew` on a 3-CP HA cluster with an external-load-balancer container produces no version-skew warning for the LB container; it only warns on genuine CP/worker skew." The current `realListNodes` blindly execs `cat /kind/version` against every container that matches the kind cluster label; LB containers have no such file, so the exec returns a non-nil `VersionErr` and `Run()` (lines 171-178) emits a `warn` listing the LB container as having an unreadable version — a pure cosmetic false-positive that breaks operator trust in the doctor output.

Output:
  - `pkg/internal/doctor/clusterskew.go` — ~5 LOC inline guard inside `realListNodes` before the `cat /kind/version` block + new `constants` import
  - `pkg/internal/doctor/clusterskew_test.go` — new `TestClusterNodeSkew_ExternalLoadBalancer_NotWarned` regression test using the existing static-entries injection seam
  - Phase SUMMARY recording behavior change + test green + race-gate green
