LATENT OBSERVATION (worth follow-up, NOT blocking):
The short-circuit check uses `filepath.Base(binaryName) == "nerdctl"`.
On macOS via lima-backed nerdctl, the binary is named "nerdctl.lima"
(NOT "nerdctl"), so the basename comparison would return false. If a
user has ONLY nerdctl.lima on PATH (no docker, no podman), the probe
would fall through to docker-style commands and fail confusingly. The
detectRuntimeBinary loop at ipamprobe.go:265 also only checks
"docker" / "podman" / "nerdctl" exact names — nerdctl.lima would not
be detected at all and the probe would return "" runtime.

This is NOT a Phase 57.4 regression — it's a pre-existing edge case
inherited from Phase 52. File as a future-phase observation if any
nerdctl.lima-only users are reported. Today, on this host, docker is
present and is correctly detected, so the latent bug is not exercised.
