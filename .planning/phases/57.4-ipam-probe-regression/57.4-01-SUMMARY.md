## Decisions Made

1. **ESCALATE: Root cause is --privileged, not the format template.** The CONTEXT.md stop-rule fired on Task 1. The plan had locked `{{(index .NetworkSettings.Networks "...").IPAddress}}` as the fix template, but the diagnostic showed the probe container reached the kind network correctly — the `range .NetworkSettings.Networks` range itself was empty because Docker Desktop 4.73.0 does not populate `NetworkSettings.Networks` for unprivileged containers. The index-template fix would have failed for the same reason. Adding `--privileged` is the minimal, correct fix.

2. **PLAN fix shape was superseded by ESCALATE finding.** The `--network=none + explicit network connect + index template` approach specified in `must_haves.truths[3]` and `must_haves.truths[2]` was NOT implemented. These are documented as drops in the PRAGMATIC scope: the evidence did not support those changes.

3. **nerdctl.lima basename fragility filed as low-severity concern.** During nerdctl UAT, VerdictUnsupported fired (correct outcome) but via the `network disconnect`/`network connect --ip` error path, NOT via the `binary == "nerdctl"` basename check. The basename check does not match `nerdctl.lima`. Filed for a future phase — not blocking Phase 57.4 or 58.

4. **Phase 58 unblock.** Phase 57.3 closed 2026-05-17. Phase 57.4 closes 2026-05-19. Both gates satisfied. Phase 58 is unblocked for the `hack/uat-47-ha-smoke.sh` test_09 re-run.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 4 - Architectural ESCALATE] PLAN fix shape (index template + --network=none) was wrong; switched to --privileged (Alt E)**
- **Found during:** Task 1 (diagnostic capture)
- **Issue:** CONTEXT.md locked `{{(index .NetworkSettings.Networks "<probeNet>").IPAddress}}` + `--network=none` as the fix shape. Diagnostic showed `docker inspect --format '{{json .NetworkSettings.Networks}}' <probe>` returns `{}` (empty object) when the probe runs without `--privileged` on Docker Desktop 4.73. The range template and the index template both fail identically on an empty Networks map. The cause is a capability/privilege gap, not a template bug.
- **Fix:** Added `--privileged` to the probe `docker run` call only. The `--network=none` + explicit `docker network connect` step was NOT added (no-op for the bug). The index template was NOT used (the existing range template works correctly once NetworkSettings is populated).
- **Files modified:** `pkg/internal/doctor/ipamprobe.go` (one flag added at the docker run invocation)
- **Verification:** Task 3 RED test `TestIPAMProbe_EmptyNetworkSandbox_ReturnsInvalidIP` asserts the bug-of-record; Task 4 GREEN test `TestIPAMProbe_PrivilegedFlag` asserts the fix; macOS Docker Desktop UAT all 3 tests PASS.
- **Committed in:** `843d1518` (fix-shape lock), `de974495` (GREEN implementation)

## Issues Encountered

- **UAT marker emoji stripped by strings(1):** The UAT freshness gate used `strings ./bin/kinder | grep -qF "⚠️ IPAM probe..."`. The `strings(1)` tool strips multi-byte UTF-8 sequences, so the emoji was never found. Fixed in `2e0fc678` by dropping the emoji from the marker string.
- **test_01 bash grep false-positive:** The initial `grep -c '"ip-pinned"'` would fail because `ip-pinned` is a substring inside a JSON string (not a standalone JSON value). Fixed in `9f202c2b` by using `grep -q '"status":"ok"'` paired with the `ipam-probe` check filter.
- **Podman INCONCLUSIVE:** The podman environment could not pull images because a gcloud credential helper was configured for `docker.io`. This is a user environment constraint, not a Phase 57.4 finding. Documented in `57.4-01-uat-macos-podman.txt`.
