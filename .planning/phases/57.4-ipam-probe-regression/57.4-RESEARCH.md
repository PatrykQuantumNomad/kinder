## Summary

Phase 57.4 is a targeted bug fix in `pkg/internal/doctor/ipamprobe.go`. The `{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}` Go template, when a container is attached to more than one Docker network, concatenates all IP addresses into a single string with no delimiter. On macOS Docker Desktop the probe container appears to acquire a second network attachment (likely `bridge` or the host network), producing a concatenated output like `"172.200.0.5invalid IP"` or just the string `"invalid IP"` when the second network entry has an empty `.IPAddress`. The `net.ParseIP` call then rejects this concatenated result and falls back to `VerdictCertRegen` with the misleading message `inspect returned invalid IP "invalid IP"`.

The fix is to replace both `{{range}}` inspect templates with `{{(index .NetworkSettings.Networks "<probeNet>").IPAddress}}` — selecting the specific network by name — and to decouple container startup from network attachment by using `--network=none` + a separate `docker network connect` step. This eliminates multi-network concatenation as a variable and makes the probe semantically precise: it asks for the IP assigned by the network it created. A single `inspectProbeIP(binary, probeName, netName string) (string, error)` helper centralises the template and ParseIP validation to one place.

All other `NetworkSettings.Networks` consumers across the codebase use either: `{{range}}` (with comma/space delimiters that detect multi-value output differently), `{{.NetworkSettings.Networks.kind.IPAddress}}` (dot-access hardcoded to "kind" network — safe as those containers always join exactly the `kind` network), or `{{range $k, $v := ...}}{{$k}}` (which iterates keys, not IPs). Only the two probe call sites in `ipamprobe.go` share the exact bug shape.

**Primary recommendation:** Fix both `ipamprobe.go` inspect templates to use `{{(index .NetworkSettings.Networks "<probeNet>").IPAddress}}`, add the `--network=none` + `network connect` two-step for probe container start, centralise in `inspectProbeIP`, add loud-log on ParseIP rejection, add ip-pin verdict surfacing at create time, add RED→GREEN unit test, and run the 4-env UAT matrix.

## Template Syntax Confirmation

**CONTEXT.md target:** `{{(index .NetworkSettings.Networks "<probeNet>").IPAddress}}`

**Evidence from codebase that this pattern works:** [VERIFIED: live codebase read]

1. `pkg/cluster/internal/providers/docker/provider.go:255` uses nested `index` on `.NetworkSettings.Ports`:
   ```
   {{ with (index (index .NetworkSettings.Ports "%d/tcp") 0) }}
   ```
   This confirms the `index` built-in function works on Docker inspect Go template output in this codebase.

2. `pkg/internal/snapshot/etcdrestore.go:188` uses dot-access syntax `{{.NetworkSettings.Networks.kind.IPAddress}}` for a statically known network name. The `(index .NetworkSettings.Networks "<name>")` form is the dynamic equivalent — same access semantics, allows a variable network name.

3. The probe's `probeNet` is a variable (`"kinder-ipam-probe-" + suffix`), so dot-access with a literal is not an option. The `index` form is required.

**Format string required for `fmt.Sprintf`:** Since `probeNet` is a variable, the template must be constructed dynamically:

```go
// inspectProbeIP helper (Task 3)
func inspectProbeIP(binary, probeName, netName string) (string, error) {
    tmpl := fmt.Sprintf(`{{(index .NetworkSettings.Networks "%s").IPAddress}}`, netName)
    lines, err := kindexec.OutputLines(ipamProbeCmder(binary,
        "inspect", "--format", tmpl, probeName,
    ))
    if err != nil {
        return "", err
    }
    ip := strings.TrimSpace(strings.Join(lines, ""))
    return ip, nil
}
```

The `ParseIP` validation stays in `ProbeIPAM`, not inside `inspectProbeIP` — keeping the helper simple and testable.

**`--network=none` + `docker network connect` two-step:** [ASSUMED] — Docker supports `--network=none` at `docker run` time to start a container with no network attachment; `docker network connect <net> <container>` then attaches the specific network. This pattern eliminates the default bridge attachment that Docker Desktop may add silently. The `network connect` call for the probe network is added as a new Step 2.5 between the current Step 2 (`run`) and Step 3 (`inspect`). The existing Step 2 changes `--network probeNet` to `--network=none`. This approach is consistent with the `docker network connect` calls in `ippin.go:155-170`.

## Common Pitfalls

### Pitfall 1: Updating seqCmder call counts
**What goes wrong:** After adding the `network connect probeNet probeName` call as Step 2.5, all existing `seqCmder([]seqResponse{...})` arrays have the wrong response count. Tests that were passing will panic with "more calls than expected responses."
**Why it happens:** `seqCmder` is strict — it panics on over-consumption by design.
**How to avoid:** Update every test's `seqResponse` slice to add a new `{output: "", err: nil}` entry at position index 2 (0-indexed: after `run`, before `inspect`). The cleanup calls at the end stay the same.
**Checklist:** 5 tests to update (see Test Infrastructure section above).

### Pitfall 2: Template quoting in fmt.Sprintf
**What goes wrong:** `fmt.Sprintf(`{{(index .NetworkSettings.Networks "%s").IPAddress}}`, netName)` — if `netName` contains `"` characters, the template breaks.
**Why it happens:** Docker probe network names are `"kinder-ipam-probe-" + suffix` where suffix is `time.Now().UnixNano()` — digits only. No quotes possible.
**How to avoid:** No action needed for production code. Add a comment documenting this assumption.

### Pitfall 3: `realInspectState` comment at ipamprobe.go:115
**What goes wrong:** The comment at line 115 says "Use the same `{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}` format as realInspectState uses the State.Status format — consistent pattern." After the fix this comment will be stale.
**How to avoid:** Update the comment to reflect the new template and rationale.

### Pitfall 4: Docker provider test `TestProvisionLogsWarnOnProbeError`
**What goes wrong:** `pkg/cluster/internal/providers/docker/provider_ippin_test.go` has a test `TestProvisionLogsWarnOnProbeError` that injects `VerdictCertRegen` with `"docker too old for --ip"` and asserts the warn log fires. After Task 6 adds the ip-pin announcement, a parallel test asserting the ip-pin path prints the expected Infof should be added.
**How to avoid:** Task 6 adds both the production code change AND a test asserting the new log line.

### Pitfall 5: Podman provider symmetry
**What goes wrong:** Only fixing the docker provider for Task 6 (ip-pin announcement) but forgetting the podman provider, which has identical code at `pkg/cluster/internal/providers/podman/provider.go:121-130`.
**How to avoid:** Task 6 must update both `docker/provider.go` and `podman/provider.go`.

### Pitfall 6: Wrong claim about `TestIPAMProbe_CleanupOnEarlyFailure` step count
**What goes wrong:** If `run` fails at call 2, the new `network connect` at call 2.5 never executes — control jumps to the defer cleanup. This test is unaffected by the step count change.
**Why:** The defer runs `rm -f` and `network rm` only; it does not run `network connect` again. The test correctly counts 4 responses (network create, run, rm -f, network rm).

// inspectProbeIP fetches the IP address assigned to probeName on the specified
// network. Uses index-by-network-name template to avoid multi-network

func inspectProbeIP(binary, probeName, netName string) (string, error) {

## State of the Art

| Old Pattern | New Pattern | Why Changed |
|-------------|-------------|-------------|
| `{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}` | `{{(index .NetworkSettings.Networks "<name>").IPAddress}}` | Range concatenates all network IPs with no delimiter; Docker Desktop may attach probe to bridge network in addition to probe net |
| `docker run --network probeNet` | `docker run --network=none` + `docker network connect probeNet` | Eliminates implicit multi-network attachment from Docker Desktop's default bridge behavior |

   - What we know: `net.ParseIP` is receiving the literal string `"invalid IP"` (with a space). The `%q` formatter in the error message proves this.

   - What's unclear: Whether macOS Podman's `network connect` semantics after `--network=none` are identical to Docker's.
   - Recommendation: The podman UAT env in the 4-env matrix will confirm. The code change is symmetric.
