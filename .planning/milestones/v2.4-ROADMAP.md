# Milestone v2.4: Hardening

**Status:** SHIPPED 2026-05-31
**Released as:** `v1.6` (public release tag — kinder's public version line; v2.4 is the internal milestone number)
**Phases:** 52-58 (+ inserted 57.1, 57.2, 57.3, 57.4)

## Overview

Closed v2.3 tech debt, brought all addons to current stable (or documented holds), and fixed the HA pause/resume etcd-TLS architectural gap discovered in v2.3. The HA fix grew from a single phase (52) into a five-phase chain (52 + 57.1/57.2/57.3/57.4) as live UAT on macOS Docker Desktop peeled back stacked upstream defects — the Envoy LB never re-applied its dynamic xDS config on resume, `discoverLBIPv6` derived IPv6 mode from the docker network rather than the cluster spec, the cert-regen fallback was broken on all HA stacks (never live-tested), and the IPAM probe regressed on Docker Desktop 4.73.0. Unblocked distribution UX via macOS ad-hoc code-signing in GoReleaser and a blocking Windows PR-CI cross-compile step, eliminated the `allChecks` test race, fixed two doctor cosmetic-output bugs, and closed both carried-forward v2.3 live-UAT items with committed evidence against the final binary.

## Milestone Goal

Close v2.3 tech debt, bring all addons to current stable, fix the HA pause/resume etcd-TLS architectural gap, and unblock distribution UX via macOS ad-hoc signing and a Windows PR-CI build step.

## Phase Ordering Rationale

**Dependency chain:**
```
Phase 52 (etcd peer-TLS / IP pinning)  [highest blast radius; isolated]
  → Phase 53 (addon bumps + SYNC-05)   [sequential sub-plans; offlinereadiness.go final]
    → Phase 56 (DEBT-04 race fix)       [must precede Phase 57; same package]
      → Phase 57 (doctor cosmetics)     [depends on race-clean baseline]
        → Phase 57.1 (LB reapply fix)   [INSERTED; UAT test_09 regression]
          → Phase 57.2 (LB IPv6 detect) [INSERTED; fixes a 57.1 sub-regression]
            → Phase 57.3 (HA cert-regen recovery) [INSERTED IPv6-only → SCOPE EXPANDED to all HA stacks]
            → Phase 57.4 (IPAM probe regression)  [INSERTED; sibling of 57.3 — both block 58]
              → Phase 58 (live UAT closure) [MUST run against final binary]

Phase 54 (macOS signing)   — independent of source code; starts after Phase 52
Phase 55 (Windows CI)      — independent of source code; starts after Phase 52
```

**Why Phase 52 first:** PITFALLS item 1 flags cert/network ops on running containers as catastrophic. Isolating Phase 52 gives all subsequent testing a working HA resume path.
**Why Phase 56 precedes Phase 57:** Both touch `pkg/internal/doctor/`; the race-clean `runChecks` refactor must land before cosmetic fixes add new test cases.
**Why Phase 58 last:** Pitfall 23 (stale binary trap). Live UAT against a binary missing any v2.4 change produces misleading evidence; Phase 58 plans hard-fail if the build marker doesn't match.

- Ad-hoc codesign on macos-latest, not notarization — AMFI on Apple Silicon kills unsigned arm64 binaries; ad-hoc (hash-only) signature satisfies AMFI with zero certificate/cost overhead; full Developer ID + notarization deferred (DIST-03)
- IP-pinning preferred over cert-regen for HA resume (k3d precedent); cert-regen is the documented fallback; Docker IPAM feasibility probe is the create-time gate
- ip-family derived from a cluster-authoritative create-time label (`io.x-k8s.kinder.ip-family`), not the docker network's `EnableIPv6` flag
- DEBT-04 fixed by parameter injection (`runChecks([]Check)`), NOT synchronization — production read path stays lock-free
- Distroless addon images: assert `runAsNonRoot: true` enforcement, not a specific `runAsUser` UID via manifest jsonpath
- Windows DIST-02 delivered at workflow level; merge-level branch protection deferred to a future CI-policy phase

- Envoy LB lost all upstreams on resume; `discoverLBIPv6` rendered IPv6-only listeners on IPv4 clusters
- Cert-regen recovery crash-looped kube-apiserver (etcd TLS handshake) on all HA stacks

- `allChecks` data race under `t.Parallel()`; `cluster-node-skew` LB false-positive; `cluster-resume-readiness` raw JSON dump
